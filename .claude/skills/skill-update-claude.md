# CLAUDE.md 更新スキル

タスク完了時に `.claude/CLAUDE.md` の変更履歴セクションを更新するスキルです。
TASKS.md の更新と合わせて使うことが多いですが、独立して呼び出すこともできます。

---

## 手順

### 1. 情報を収集する

| 項目 | 取得方法 | 例 |
|------|---------|-----|
| タスク ID | ユーザー指示 or 会話コンテキスト | `P1-T5` |
| 完了日 | 今日の日付 | `2026-05-20` |
| 変更の要約 | タスク成果を 1 行で。主要ファイル・技術的ポイントを含める | `ゲームループ。loop.ts — accumulator + スパイク対策` |

### 2. CLAUDE.md を読み込む

```
Read .claude/CLAUDE.md
```

**変更履歴テーブル**を探す。典型的なパターン:

```markdown
## N. 変更履歴

| 日付 | バージョン | 変更 |
|---|---|---|
| ... | ... | ... |
```

セクション番号やヘッダー名はプロジェクトにより異なる（「変更履歴」「Changelog」「Change History」など）。
テーブルの最終行を特定し、そのバージョン番号を確認する。

### 3. 新しい行を追加する

テーブル最終行の直後に新しい行を追加する。

- **日付**: 今日の日付
- **バージョン**: 最終行のバージョンを patch increment（`1.0.3` → `1.0.4`）
- **変更内容**: `{タスクID} 完了（{タスク名}）。{主要ファイル・成果の要約}`

**例:**
```
| 2026-05-20 | 1.0.4 | P1-T5 完了（ゲームループ）。`apps/web/src/game/loop.ts` — accumulator パターン + スパイク対策 + jsdom テスト環境。テスト 6 件全 pass |
```

### 4. 要約の書き方

変更要約には以下を含めると、後から履歴を追いやすくなる：

- **何を作ったか**: 機能名やモジュール名
- **主要ファイルパス**: バッククォートで囲む（1-2 個まで）
- **技術的ハイライト**: アルゴリズム名、パターン名、特筆すべき対策
- **テスト件数**: テストを追加した場合

1 行に収める。詳細は TASKS.md の「学び」セクションに書くため、CLAUDE.md は概要にとどめる。

### 5. 編集を適用する

Edit ツールでテーブル最終行の後に新しい行を挿入する。

---

## TASKS.md の変更履歴との整合

TASKS.md と CLAUDE.md の両方に変更履歴がある場合、**同じバージョン番号**を使う。
TASKS.md を先に更新してからこのスキルを使うと、バージョン番号を合わせやすい。

---

## 注意事項

- 変更履歴テーブルが存在しない場合は追加しない。ユーザーに確認する
- バージョン番号の形式は既存パターンに合わせる
- テーブルの列数やヘッダー名が異なるプロジェクトもある。既存行のフォーマットに揃える
