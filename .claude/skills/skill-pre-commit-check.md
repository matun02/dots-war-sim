# コミット前の必須チェック（セルフレビュー + ウェブテスト + 自動テスト）

タスク実装完了後、コミット・プッシュ前に **必ず** このスキルの全ステップを実施すること。
1つでも不合格の場合はコミットしない。

---

## 1. セルフレビュー

### 1a. diff 確認
```bash
git diff --stat
git diff
git status
```
- 意図しないファイルが含まれていないか
- デバッグコード（`console.log`, `debugger`, `// DEBUG`, `// TODO`, `// HACK`）が残っていないか
- テスト用の一時変更（色・alpha・パラメータ変更等）が戻されているか

### 1b. 決定論チェック（`core/sim/` 変更時は必須）
`CLAUDE.md` §4.3 の禁止事項に違反がないか確認:
- [ ] `Math.random()` → `rng.next()` を使っているか
- [ ] `Date.now()` / `performance.now()` → `state.tick` を使っているか
- [ ] `Map`/`Set` のイテレーション順依存がないか
- [ ] `Array.sort` の比較関数が全順序か（tie-break に ID を使用）
- [ ] `for...in` を使っていないか
- [ ] 外部 I/O（fetch, console, DOM）がないか
- [ ] `async/await` がないか

### 1c. アーキテクチャ境界チェック
- [ ] `core/` から `apps/` を import していないか（CLAUDE.md §3.1）
- [ ] `core/sim` 内で副作用がないか
- [ ] `render/` のみが PixiJS を import しているか（CLAUDE.md §4.5）
- [ ] `ui/` のみが Svelte コンポーネントか（CLAUDE.md §4.6）
- [ ] 触ったディレクトリが 2 つ以内か（CLAUDE.md §7.2）

### 1d. パフォーマンスチェック
- [ ] ゲームループ内（onTick / onRender）で不要なオブジェクト生成がないか
- [ ] 重い計算は onTick（30Hz）側にあるか（onRender は 60Hz なので軽量に）
- [ ] 影響マップ等の重い計算はキャッシュされているか

---

## 2. 自動テスト

```bash
pnpm -r typecheck && pnpm -r test && pnpm lint
```

3 つ全てが green であること。1 つでも失敗したら原因を修正してから再実行。

---

## 3. ウェブテスト（ブラウザ実動作確認）

### 3a. サーバ起動
```bash
pnpm --filter @dots-war-sim/web dev
```

### 3b. ブラウザで確認
以下のチェックリストを上から順に確認する:

#### 基本動作
- [ ] タイトル画面が表示される
- [ ] Start Game クリックでゲームが開始される
- [ ] コンソールにエラーが出ていない

#### ゲームプレイ
- [ ] ユニットがマップ上に表示される
- [ ] ドラッグで矩形選択ができる
- [ ] 右クリックで移動命令が出せる
- [ ] 都市クリックで生産切替ができる
- [ ] AI（Player 2）が動作している

#### 当該タスク固有の確認
- [ ] 今回の変更が意図通りに動作しているか目視確認
- [ ] 変更箇所以外の既存機能が壊れていないか確認

#### パフォーマンス
- [ ] 60 FPS が維持されている（体感で滑らか）

### 3c. 注意事項（CLAUDE.md §7.5）
- WebGL Canvas のスクリーンショットは黒画面になるため、JS 状態検証（`javascript_tool`）を併用する
- Chrome 拡張のボタンクリックは不安定 → JS の `.click()` や `PointerEvent` dispatch を優先する
- 特定条件のライブ検証が必要な場合は、一時的にパラメータを変更して確認後に必ず元に戻す

---

## 4. 全チェック通過後

上記 1〜3 の全ステップが通過したら、`skill-commit-convention.md` に従いコミット・プッシュに進む。
