# TASKS.md 更新スキル

タスク完了時に `.claude/TASKS.md` を更新するスキルです。
タスク完了報告のタイミング、または「TASKS.md を更新して」と指示されたときに使ってください。

---

## 手順

### 1. 情報を収集する

更新に必要な情報を揃える。不足している場合はユーザーに確認する。

| 項目 | 取得方法 | 例 |
|------|---------|-----|
| タスク ID | ユーザー指示 or 会話コンテキスト | `P1-T5` |
| 完了日 | 今日の日付 | `2026-05-20` |
| コミットハッシュ | `git log --oneline -1` の先頭 7 文字 | `12f1fab` |
| 実績（所要時間） | ユーザーに確認、または会話から推定 | `30 分` |
| 学び | 会話中の技術的発見・注意点を要約 | IEEE 754 対策が必要だった等 |
| 変更履歴の要約 | タスク成果を 1 行で | ゲームループ + テスト 6 件 |

### 2. TASKS.md を読み込む

```
Read .claude/TASKS.md
```

以下の 4 箇所を特定する：

1. **タスク見出し行** — `## P1-T5: ゲームループ（クライアント側）` のような行
2. **受け入れ基準** — その見出し配下の `- [ ]` チェックボックス群
3. **見積行の直後** — `**見積**:` 行の後に `実績` と `学び` を追加する位置
4. **変更履歴テーブル** — ファイル末尾付近の `| 日付 | バージョン | 変更 |` テーブル

### 3. 見出しに完了マークを追加する

**Before:**
```
## P1-T5: ゲームループ（クライアント側）
```

**After:**
```
## P1-T5: ゲームループ（クライアント側） ✅ 完了 (2026-05-20, commit `12f1fab`)
```

フォーマット: `{既存の見出し} ✅ 完了 ({日付}, commit \`{hash}\`)`

### 4. 受け入れ基準を全てチェック済みにする

タスク配下の `- [ ]` を全て `- [x]` に置換する。
受け入れ基準が実際に満たされていることを事前に確認してから行う（テスト結果、grep 結果など）。

### 5. 実績と学びを追加する

`**見積**:` 行の直後に以下を挿入する：

```markdown
- **実績**: {所要時間}
- **学び**: {技術的な発見・注意点・ワークアラウンドの要約}
```

学びの内容は、将来の同種タスクで役立つ実践的な知見に絞る。
会話中に得られた具体的な知見（ライブラリの挙動、設定の注意点、浮動小数点の罠など）を含める。

### 6. 変更履歴テーブルに行を追加する

テーブル最終行の次に新しい行を追加する。

- **日付**: 今日の日付
- **バージョン**: 最終行のバージョンを patch increment（例: `1.0.3` → `1.0.4`）
- **変更内容**: `{タスクID} 完了マーク（commit \`{hash}\`）。{成果の要約}`

**例:**
```
| 2026-05-20 | 1.0.4 | P1-T5 完了マーク（commit `12f1fab`）。ゲームループ + テスト 6 件 + jsdom 環境設定 |
```

### 7. 編集を適用する

Edit ツールで上記 4 箇所を順に更新する。
一度に複数箇所を変更するときは、ファイル内で上から下の順に編集すると安全（行番号ずれを防ぐ）。

---

## 注意事項

- 既に `✅ 完了` が付いているタスクは二重更新しない
- バージョン番号の形式はプロジェクトの既存パターンに合わせる（SemVer、連番、日付ベースなど）
- 変更履歴テーブルが存在しない場合は、ユーザーにテーブルを作るか確認してから追加する
