## 背景

P2-T4.1（前線・領土システム再設計）で初期ユニット配置と影響マップの刷新は完了したが、
ウェブテストで以下 4 点の改善要望がユーザーから出た:

### 改善 1: 初期ユニットを密集隊形で配置
- 現状: `init.ts` が自陣半分にランダム散布（Rng で座標をランダム選択）
- 要望: 敵兵士と味方兵士が **縦・横・斜めの隊形**（ライン状）で密集して並ぶ
- 配置方向は spawn 都市の相対位置から自動判定:
  - 左右配置 → 縦列（vertical column）
  - 上下配置 → 横列（horizontal row）
  - 対角配置 → 斜め列（diagonal line）
- 侵入不可地形（mountain=1, water=3）には配置しない
- 隊形は spawn 都市から敵方向に向かって、都市の前方に展開する

### 改善 2: 後方拠点の明確化
- 「後方の拠点は自身が確保済みの拠点」という認識を強化する
- 隊形配置の位置を spawn 都市と中央の間に置き、都市が明確に「後方」になるようにする
- 影響マップの都市重み（city_weight=300）は P2-T4.1 で既に実装済みなので、配置位置の調整がメイン

### 改善 3: ユニット同士の当たり判定（衝突分離）
- 現状: ユニット同士は重なり放題（同じ座標に何体でも乗れる）
- 要望: ユニット同士に当たり判定を付ける
- 実装: `moveUnits()` の後に **衝突分離ステップ** を追加
  - SpatialHash を使って近傍ユニットを検索
  - 重なっているユニット同士を押し出す（separation force）
  - 味方同士も敵同士も分離する
  - 1 tick で完全分離する必要はない（数 tick かけて自然に広がる）

### 改善 4: ユニットの体力・大きさを 3 倍
- light HP: 1 → **3**
- heavy HP: 5 → **15**
- 描画サイズ（UNIT_RADIUS）も 3 倍:
  - light: 0.25 → **0.75**
  - heavy: 0.35 → **1.05**
- 攻撃力・速度・その他のパラメータは変更しない
- 戦闘が長引くことで、戦略性が増し、前線の動きがよりダイナミックになる

## これからやるタスク
**P2-T4.2: ユニット隊形配置・衝突分離・HP/サイズ 3 倍**

ゲームの見た目と操作感を改善する 4 つの変更を実施する。

### 仕様

#### 1. 隊形配置 (`init.ts`)

spawn 都市の位置から敵方向を判定し、ユニットを隊形で配置する:

```ts
// 1. spawn都市から敵spawn都市への方向ベクトルを計算
// 2. その直交方向が隊形の並び方向
// 3. spawn都市から敵方向に offset（例: 5セル）前進した位置を隊形中心とする
// 4. 隊形中心から直交方向に 1.5セル間隔でユニットを配置
// 5. 配置先が侵入不可地形ならスキップして次の位置を試す

const FORMATION_OFFSET = 5;      // spawn都市から前方への距離
const FORMATION_SPACING = 1.5;    // ユニット間隔（衝突半径を考慮）
```

方向判定ロジック:
- `|dx| > |dy| * 2` → 横配置（左右対称マップ）→ 縦列隊形
- `|dy| > |dx| * 2` → 縦配置（上下対称マップ）→ 横列隊形
- それ以外 → 斜め隊形

**重要**: `Rng` を使わない純粋な計算で配置する（決定論性は保持）。
Rng を使うのは、侵入不可地形で配置できない場合のフォールバックのみ。

#### 2. 衝突分離 (`steps/separate-units.ts` 新規作成)

```ts
export function separateUnits(state: GameState): void;
```

- SpatialHash で近傍検索（半径 = 分離距離）
- 2 ユニットの距離が `SEPARATION_DIST` 未満なら、互いに反対方向に押し出す
- 押し出し量 = `(SEPARATION_DIST - dist) * 0.5`（半分ずつ負担）
- 距離 0（完全重複）の場合は id の小さい方を +x、大きい方を -x に押す（決定論的）
- マップ境界チェック: 押し出し先がマップ外なら制限
- 山・水地形チェック: 押し出し先が侵入不可なら押し出さない

```ts
const SEPARATION_DIST = 0.6; // ユニット同士の最小距離
```

### 実装要件
1. **決定論必須** — `separateUnits` に `Math.random()` 禁止。距離 0 の場合は ID でタイブレーク（CLAUDE.md §4.3）
2. **2 ディレクトリ制限** — `packages/core` + `apps/web`（CLAUDE.md §7.2）
3. **純関数/副作用なし** — `separateUnits` は `GameState` を in-place 変更（他の step と同様）
4. **既存テストの更新** — HP 変更により `produce-units.test.ts` や `resolve-combat.test.ts` 等で HP=1 を前提としたアサーションが壊れる可能性あり。全て更新すること
5. **パフォーマンス** — `separateUnits` は毎 tick 呼ばれるので、SpatialHash を使い O(n) に近い計算量にすること
