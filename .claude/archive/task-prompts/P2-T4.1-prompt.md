## 背景・問題の経緯

P2-T4（前線描画）のマーチングスクエア法実装は完了済み（commit `41c8257`、テスト 8 件 green）。
しかしウェブテストで以下の **ゲーム設計上の問題** が判明した:

### 問題 1: 初期ユニット配置が空
- `createInitialState()` が `units: []` で開始する
- ゲーム開始直後は前線が存在せず、都市からユニットがスポーンして歩き始めるまで何も起こらない
- **本家 War of Dots の挙動**: 開始時からユニットがマップ上に並んでおり、すぐに戦闘が始まる。都市は死んだユニットの補充拠点

### 問題 2: 影響マップの拡散範囲が狭すぎ
- 現在の `computeInfluenceMap` はガウシアン拡散 **3 回**（`DIFFUSION_ITERATIONS = 3`）
- 64×36 マップ上で影響半径は **3〜4 セル** しかない
- 結果: ユニット周囲に小さな輪っかが出るだけで、「領土」の感覚がない

### 問題 3: 後方領土の概念がない
- 影響マップはユニット位置からの拡散のみ
- 前線の後方（自陣側）が自動的に「自軍領土」として認識されない
- 結果: 前線が両軍の境界線ではなく、各プレイヤーのユニット群を囲むリングになる

## これからやるタスク
**P2-T4.1: 前線・領土システム再設計**

上記 3 つの問題を解決し、前線描画が「両軍の境界線」として正しく機能するようにする。

### 仕様

#### 1. 初期ユニット配置（`init.ts` 改修）

`createInitialState()` で各プレイヤーの自陣半分にユニットを初期配置する:

- 各プレイヤーの都市から前線方向にかけて **light ユニットを 8〜12 体** 配置
- 配置範囲: マップを左右（or 対角線）で分割し、自陣側の通行可能セルに分散
- 山岳セル（terrain=1）には配置しない
- 都市の `supplyUsed` を初期ユニット数で正しく設定する
- ★MUST: 配置位置の決定には `Rng` を使い決定論を維持する
- ★MUST: `nextEntityId` を正しくインクリメントする

```ts
// イメージ
export function createInitialState(
  map: MapDef,
  players: Player[],
  seed: number,
): GameState {
  // ... 既存の city 初期化 ...
  const rng = new Rng(seed);
  const units: Unit[] = [];
  // 各プレイヤーのスポーン都市から自陣半分にユニットを配置
  // 配置ロジック: 都市を中心に放射状、または自陣エリアのランダムな通行可能セル
  // ...
  return { ..., units, nextEntityId: units.length };
}
```

#### 2. 影響マップ改善（`influence-map.ts` 改修）

影響マップの拡散を大幅に広げて「領土」の感覚を出す:

**方針A（推奨: シンプル）**: 拡散回数を大幅増加
- `DIFFUSION_ITERATIONS` を 3 → **8〜12** に増やす
- 影響半径が 8〜12 セルに広がり、近くのユニット群の影響が繋がる
- 計算コスト増加は 5tick ごとの再計算で吸収可能か要検証

**方針B（代替案）**: 都市ベースの基礎影響を加算
- 所有都市セルに大きな基礎影響（city_weight=300〜500）を加算
- 都市周辺が広く「領土」として表示される
- ※ P2-T7 で都市重みを追加予定だったが、前倒しで実装

**方針C（代替案）**: フラッドフィル型の領土計算
- ユニットの影響ではなく、マップの各セルを最寄りプレイヤーで塗り分ける
- Voronoi 的アプローチ
- 計算が重くなる可能性がある

★判断基準: 方針A を最初に試し、前線が「両軍の境界線」として見えるか確認。不十分なら B を追加。C は過剰設計になる可能性が高いため回避。

#### 3. 前線描画の調整（`frontline.ts` — 必要に応じて）

- マーチングスクエアのロジック自体は変更不要（正常動作済み）
- 影響マップの入力が変われば出力も自然に変わる
- ★ただし: 拡散を大きくした結果、セグメント数が増えすぎてパフォーマンスに影響する場合は間引き検討
